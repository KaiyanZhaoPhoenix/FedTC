# 诊断实验方案与报告模板：验证 `Dir(0.1)` 下“紧缩过滤饿死诚实少数派”现象

> **文档目的**：本实验不引入 RL 或 FedTC 新算法，专门用于在**纯正现代联邦学习设置（$K=60$, $\mathrm{Dir}(0.1)$, CIFAR-100）**下，以最小成本、无人工刻意分组的方式，客观验证核心前提是否成立：
> **“收紧现有客户端评估/过滤规则虽然能压制恶意攻击者，但会系统性压低分布最偏斜的诚实少数派权重，并造成其对应类别/边缘客户端性能被长期饿死。”**

---

## 一、精确实验配置（可直接照抄进代码）

### 1.1 数据集与无偏划分设置
- **数据集**：`CIFAR-100`（50,000 张训练图 / 10,000 张测试图，100 类）。
- **骨干网络**：**`ResNet-18 (GroupNorm 版)`**。
  > **工程关键提醒**：在 `Dir(0.1)` 强异质下，标准 `ResNet-18` 的 `BatchNorm` 会因本地统计量剧烈偏移导致连 `FedAvg (无攻击)` 都掉点严重，从而掩盖“过滤误伤”本身的效果。**务必将所有 `BatchNorm2d` 替换为 `GroupNorm`（如 `num_groups=8` 或 `16`），并使用 CIFAR 专用的 `3x3 conv1 + 无 maxpool` 结构。**
- **客户端总数与恶意人数**：
  - 总客户端数 $K = 60$，恶意比例 $\rho = 20\%$ $\implies$ **48 个诚实客户端 + 12 个恶意客户端**（高压对比组可追加 18 个恶意即 $30\%$）。
- **防混杂的数据划分规则（确保无攻击基线可学全 100 类）**：
  - 将全部 50,000 张训练样本按标准 **`Dir(α = 0.1)`** 分配给 **48 个诚实客户端**（最小样本数保护如每客户端 $\ge 100$ 张，确保 100 个类在诚实总体中都有覆盖，不出现“某个类本来就全分给了恶意客户端”的伪掉点）；
  - 12 个恶意客户端按同分布随机抽取影子本地数据（用于构造依赖本地训练梯度的攻击，如 Sign-flip / Label-flip / Mimic）。
- **每轮抽样设置**：
  - 每轮无放回抽样 **$n = 20$ 个客户端**（采样率 $C = 1/3$）。
  - *统计学依据*：经超几何分布核算，在 $K=60, M=12$ 时，每轮抽 $20$ 人出现“恶意过半（$\ge 10$ 人）”的概率仅 **$0.01\%$**（即使在 $M=18$ 时也仅 **$1.93\%$**），不会因小样本抽爆而干扰静态规则稳定性。
- **本地与全局训练超参**：
  - 本地轮数 `E = 2`（充分体现非独立同分布漂移；可对比 `E = 1`），`batch_size = 64`；
  - 客户端优化器：`SGD (lr = 0.05 或 0.01, momentum = 0.9, weight_decay = 5e-4)`；
  - 服务器学习率：$\eta_t = 1.0$；总通信轮数：`T = 150` 轮；随机种子：`seeds = {0, 1, 2}`。

---

### 二、“诚实少数派”与“饿死指标”的客观界定（无任何人工分群）

数据按标准 `Dir(0.1)` 划完后，统计每个诚实客户端 $k \in \mathcal{H}$ ($|\mathcal{H}|=48$) 的本地类别频率向量 $p_k \in \Delta^{99}$，并与全体诚实平均分布 $\bar{p}$ 计算全变差距离：
$$D_k = \frac{1}{2}\|p_k - \bar{p}\|_1.$$

1. **权重统计分群（划分完一次性固定，全程跟踪）**：
   - **5 档偏离度分箱**：将 48 个诚实客户端按 $D_k$ 从小到大排列，每 9–10 人一档分为 `Bin 1`（最典型/最接近均值）$\to$ `Bin 5`（最偏斜/最极端 Non-IID）；
   - **时间线三群体对比**：
     - 蓝线 **`Typical Honest (Bottom-25% D_k, 12人)`**：最接近大盘的诚实客户端；
     - 橙线 **`Rare-Dist Honest (Top-25% D_k, 12人)`**：分布最偏斜极端的诚实少数派；
     - 红线 **`Malicious (12人)`**：恶意客户端。
2. **下游“长期饿死”靶标指标（三选二以上同框汇报）**：
   - **`Overall Test Acc`**：CIFAR-100 全测试集准确率；
   - **`Worst-20% Class Acc`（或 `Rare-Client Dominant Class Acc`）**：按“该类样本在少数几个诚实客户端里的集中度（或 Gini 系数 / 最大单客户端占比）”选出分布最集中、最少人持有的 Top-20 个稀有类，统计全局模型在这 20 个类上的平均测试精度；
   - **`Worst-20% Client Local-Dist Acc`**：用全局模型在每个诚实客户端本地标签分布（利用测试集中对应类别按 $p_k$ 加权）计算各自表现，取最差 20% 客户端的平均准确率。

### 三、对比的聚合/挑选策略与攻击设置

#### 3.1 只跑最说明问题的 6 组策略对照
1. **`FedAvg (Clean, 0恶意)`**：仅 48 个诚实客户端均匀聚合（作为无攻击理想参考线）。
2. **`FedAvg (Attacked, 12恶意)`**：不设防基准（验证攻击确实破坏整体模型）。
3. **`Loose Filter (Attacked)`**：宽松规则——例如 `Multi-Krum` 每轮选 $m = 17$（共 20 人），或 `Distance-Gate` 取大截断半径 $\tilde{\delta}_k \le 2.5$（验证“保住了少数派权重，但漏进了恶意权重”）。
4. **`Strict Filter (Attacked)`**：严格规则（至少跑 2 个典型代表）——
   - `Multi-Krum (Strict)`：每轮保守只选最核心的 $m = 10$ 人（其余权重为 0）；
   - `Tight Distance-Gate` / `Cosine-ReLU`：按中位数尺度只留 $\tilde{\delta}_k \le 1.1$ 或余弦截断加权；
   - （可选加跑 `RFA` 几何中位数重加权及 `NNM + RFA` 看看传统异质修复器在强攻击与极端偏斜下的权重分布）。
5. **`Strict Filter (Clean, 0恶意)` —— 核心对照组**：完全没有恶意攻击者，但仍开着上述严格过滤规则（最干净地剥离出“规则本身对诚实少数派的误伤”）。

#### 3.2 攻击设置（建议测 2 种典型攻击）
- **攻击 A（经典强几何攻击）：`Sign-flip`**，$\Delta\mathbf{w}_k^{(t)} \leftarrow -3.0\,\Delta\mathbf{w}_k^{(t)}$（恶意客户端基于本地样本算梯度后取反放大）。
- **攻击 B（贴近边缘异质的隐蔽攻击）：`Mimic Attack`**（参考 Bucketing ICLR'22），恶意客户端观察同轮更新或模仿某边缘诚实客户端方向做微幅扰动放大，专门测试静态几何规则在“分不清真假偏离”时的两难表现。
- **（加分动态场景）阶段开关攻击**：`0–50 轮无攻击 → 50–100 轮开启攻击 → 100–150 轮撤出攻击`，观察攻击撤出后静态严格规则对 `Top-25% D_k` 权重的持续锁死。

### 四、实验执行时每轮记录的日志字段

建议每轮保存一行 JSONL 或 CSV 日志，包含以下字段：
- `round`: 当前轮次 $t$
- `alpha_typ`, `alpha_rare`, `alpha_mal`: 当轮抽中样本里三类群体的**单客户端平均实际权重** $\bar{\alpha}_G^{(t)}$（以及各自被直接置零 $\alpha_k=0$ 的比例 `drop_rate`）
- `alpha_bin1` ~ `alpha_bin5`: 5 个偏离度分箱各自的单客户端平均权重
- `delta_bin1` ~ `delta_bin5`, `delta_mal`: 对应各组到几何中位数的平均距离 $\delta_k^{(t)}$
- `overall_acc`: 全局模型 100 类总测试准确率
- `rare_class_acc`: 分布最集中的 20 个稀有类测试准确率
- `worst20_client_acc`: 48 个诚实客户端中最差 20% 的加权测试准确率

### 五、支撑结论必画的 3 张图（建议排布）

1. **图 1：三类客户端“单人平均权重”随轮次变化轨迹（1×2 并排子图）**
   - 左图：**`Loose Filter`** vs. 右图：**`Strict Filter (Multi-Krum / Tight Gate)`**。
   - 曲线：蓝线（`Typical Honest`）、橙线（`Rare-Dist Honest`）、红线（`Malicious`）。
   - **检验标准**：左图橙线高但红线压不住；右图红线贴近 0，**但橙线同步掉到接近 0（或长期显著低于蓝线）**。
2. **图 2：偏离度分箱 $D_k$ vs. 几何距离与分配权重（因果机制图）**
   - X 轴：`Bin 1` $\to$ `Bin 5` + `Malicious`；
   - Y 轴：150 轮全局平均的几何距离 $\delta_k$（柱状）与分配权重 $\bar{\alpha}_k$（折线）。
   - **检验标准**：`Bin 5` 的几何距离明显高于 `Bin 1` 并逼近 `Malicious`，导致严格策略的权重从 `Bin 1` 到 `Bin 5` 呈单调断崖下降。
3. **图 3：整体精度 vs. 少数派/最差客户端精度（“长期饿死”铁证，1×2 并排子图）**
   - 左图：`Overall Test Accuracy` vs. Round；右图：**`Rare-Class Acc`（及附图 `Worst-20% Client Acc`）vs. Round**。
   - 曲线：`FedAvg (Clean)`、`FedAvg (Attacked)`、`Loose (Attacked)`、`Strict (Attacked)`、`Strict (Clean)`。
   - **检验标准**：左图上 `Strict` 看似保住了较高总体精度，**但右图里 `Strict (Attacked)` 甚至 `Strict (Clean)` 显著且持续地落后于 `FedAvg (Clean)`**，证实少数派被长期饿死。

### 六、结果判断与常见排查（防止走弯路）

- **什么现象算“问题被彻底证明存在”？**
  1. `Strict Filter` 下 `Rare-Dist Honest` 平均权重显著低于 `Typical Honest`（例如低 50% 以上甚至长期被踢出 $\alpha=0$）；
  2. `Strict (Clean)` 的 `Rare-Class Acc` / `Worst-20% Client Acc` 明显低于 `FedAvg (Clean)`；
  3. `Loose` 要么在强攻击下 `Overall Acc` 明显被拉垮，要么在 `FedAvg (Attacked)` 直接崩盘，形成“松则中毒、紧则饿死”的明确交叉剪刀差。
- **如果第一遍跑出来现象偏弱，优先排查这 3 处（不改数据划分本身）**：
  1. 检查是否误用了 `BatchNorm` 而非 `GroupNorm`（如果连 `FedAvg (Clean)` 的精度都上不去或震荡，全是 BN 的锅）；
  2. 检查本地更新步数：若 `E=1` 且 `lr` 太小，各客户端只走几步，异质差异还没拉开；将本地训练调至常规标准 `E=2~3`（或 `batch_size=32`），异质梯度偏离就会自然显现；
  3. 检查稀有类指标的挑选方式：确认是按“诚实客户端持有集中度”筛选的稀缺类，而非全局平均样本数一样的随机类。
