# FedTC 的动机、方法与版本

## 研究问题

服务器没有干净验证数据时，需要同时处理被污染的客户端模型更新、夸大的效用报告和伪造的验证反馈。非 IID 环境中，诚实少数客户端也可能远离多数更新；过强的几何过滤可能伤害它们。

论文目标是在抵抗攻击的同时调整聚合严格程度，并保留少数群体的表现。当前实验尚未证明这个完整目标已达到。

## 前向聚合

每轮计算更新的几何中位数，以到该中心距离的中位数归一化客户端偏离度；将效用报告转为队列内排名。然后计算：

`c = max(0, (1-lambda) + lambda * utility_rank - tau * tanh(normalized_distance / 4))`

归一化 `c` 得到聚合权重。参数域为 `lambda ∈ [0,0.5]`、`tau ∈ [1.05,1.8]`。这部分位于 `code/algorithms/fedtc/forward.py`，所有 FedTC 版本共用。

## 原版后向控制

每 H 轮从全部客户端独立抽取验证队列，报告本地留出集上的截断损失改善。极端截尾均值和抽样裕量构成奖励区间。确定性 Actor 输出 `(lambda,tau)`，上下端点 Critic 使用不同的 TD 奖励训练，PopArt 处理尺度。候选下端点价值必须超过保守动作上端点价值减容忍量，否则执行 `(0,1.35)`。

这是 DDPG 风格的确定性区间 Actor-Critic，不是 FedAA 的标准 DDPG 实现。默认 `paper` TD 忠于原稿；`consistent` 是显式的归一化修正选项。两者不可混报。

## SAC 扩展

SAC 使用随机策略、两个估计同一中点奖励的 soft Q 网络，以及另外两个不含熵奖励的端点网络。两个 SAC 版本训练方式一致，仅执行门控与否不同。经验池记录实际执行动作。详细定义见 [sac.md](sac.md)。

原控制器与 SAC 的奖励目标、归一化均不同，因此它们的结果不是纯粹的 DDPG/SAC 优化器消融。SAC 的两个 soft Q 也不是价值区间的上下界。

## 框架与比较

沿用 FedAA 的客户端划分、本地训练和测试实现；在共享协议下统一从本地训练集留出 10% 验证样本。FedTC 不访问服务器干净数据；FedAA 保留自己的服务器奖励数据，报告中必须注明这一差别。

`FedTCFixed` 的默认参数 `(0,1.35)` 与本轮调参固定组 `(0.5,1.35)` 是不同设置。原版全部回退时，实际等价于前者，不能把相对后者的差异归功于 RL。

## 证据边界

原版与 SAC 加门控在最新实验中都全部回退；无门控 SAC 会调整参数，但尚未提升准确率。单种子结果、诚实平均改善与事后最差客户端统计，都不能直接证明少数群体保护、策略价值置信覆盖或长期安全。
